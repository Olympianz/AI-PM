# AI-PM 产品设计规格 v0.1

日期：2026-08-08
状态：待用户审阅

## 1. 背景与目标

**产品定位**：面向有经验且具备 AI 基础知识的产品经理，通过 2 个月（8 周）的个性化学习，查漏补缺，达到大厂资深 AI 产品经理录用标准。

**首个用户**：作者本人。个人案例跑通闭环后，再产品化服务其他 PM。因此设计中强调「数据/内容与工具分离」，便于日后复用。

**核心逻辑**（以终为始）：

大厂录用标准（JD + 面试流程）→ 能力模型 → 能力测评 → 个性化学习路径 → 学习执行 → 跟踪复测 → 面试就绪度判定 → 回到能力模型动态更新。

**成功标准**（8 周结束时）：

1. 目标 JD 的核心能力项全部达到目标等级（L3+），关键证据能力达到 L4（有可追问的实践证据）。
2. 模拟面试（行为面 + 案例面 + 专业面）平均分达到目标线，判定为「达到录用标准」或明确列出剩余 gap。
3. 面试素材库沉淀：≥ 20 张答案卡、≥ 4 个可复述的 STAR 案例、≥ 2 份完整输出物（PRD/方案/拆解报告）。
4. 知识掌握率 ≥ 85%（基于间隔重复）。

## 2. 设计原则

1. **以终为始**：一切能力项、学习内容、题目都反向锚定录用标准。
2. **输出大于输入**：资深 PM 的差距通常在深度与表达，每天学习结构约 40% 输入、40% 练习、20% 输出。
3. **自适应闭环**：跟踪不只是统计，系统根据表现自动调整路径。
4. **JD 驱动**：手动导入 JD 后，能力模型、测评、路径、题库、就绪度标准全链路自动更新。
5. **弹性优先**：在职学习，每天最低必做 60 分钟 + 可选深度任务。

## 3. 功能模块

### M0 JD 导入与能力模型更新（新增）

**目的**：用户看到新 JD 即可导入，系统自动解析并全面更新后续所有模块。

**输入**：JD 文本（粘贴 / 文件 / URL）。

**处理流程**：

1. 解析：抽取职责、核心要求、加分项，生成结构化能力需求（能力项、行为指标、目标等级线索、权重线索）。
2. 映射：与现有能力词典比对，分三类——命中已有项 / 新增项 / 冲突项。
3. 更新：新增项自动归入知识域并生成行为指标与证据要求；权重按「出现频率 + 职责优先级」重算；目标等级按 JD 描述更新。
4. 级联：生成变更清单，标记受影响模块（测评题库、学习路径、面试题库、就绪度标准）。
5. 确认：用户审阅 diff 后一键应用；保留版本历史，可回滚。
6. 应用后：若用户处于学习周期中，自动重排未完成路径；若未开始，更新入营测评。

**冲突处理**：多个 JD 要求矛盾时，生成对比清单，由用户选择「取并集 / 取最高等级 / 手动指定」。

### M1 能力模型库

**目的**：把录用标准转成可测、可追踪的结构化能力词典。

**结构**：知识域 × 能力项 × 行为指标 × 证据要求 × 权重 × 目标等级。

**等级定义（L1-L5）**：

- L1 概念了解：听说过，能说出定义。
- L2 理解原理：能解释机制、适用场景与局限。
- L3 独立应用：能在真实场景独立完成一项任务（面试可现场演示）。
- L4 实践证据：有 STAR 案例 / 输出物，经得起追问。
- L5 专家引领：能定义最佳实践、带教、影响组织。

**目标等级**：资深大厂标准 = 核心能力 L3+，有明确证据要求的能力 L4。

### M2 能力测评

**目的**：基线诊断，输出能力画像与优先补强清单。

**组成**：

1. 入营问卷：背景（年限、方向、目标公司/职级、每日可用时间、已有 AI 使用经验与作品）。
2. 客观题：按知识域自适应抽题，测知识广度与深度。
3. 案例题：开放题 + rubric 评分（AI 初评 + 用户复核校准），测思维深度，权重高于客观题。

**输出**：能力雷达图、优先补强清单（3-5 项）、学习计划参数（强度、节奏）。

**复测**：每两周一次，对比雷达变化，作为自适应调整依据。

### M3 个性化学习路径

**目的**：把 2 个月拆成可执行、可调整的计划。

**结构**：8 周 × 4 个冲刺周期（每周期 2 周：学习 → 复测 → 复盘调整）；每日 2-3 小时，任务由知识输入 / 案例练习 / 项目拆解 / 输出物 / 面试训练自动组装。

**弹性机制**：

- 每日最低必做 60 分钟 + 可选深度任务。
- 连续 3 天完成率 < 60% 时自动减负并调整周计划。
- 能力达标项自动降级，落后项自动加练。

### M4 学习与练习引擎

**目的**：提供内容资产与练习模板，并沉淀面试素材。

**内容资产**：

- 知识点卡（按能力项组织，配合间隔重复）。
- 案例库（真实产品案例拆解）。
- GitHub 项目拆解卡：目标 / 架构 / 关键设计 / tradeoff / 产品化启示 / 可考的面试题。筛选标准是「业务场景相关度 + 设计可讲性」，不只看 star 数。
- 面试真题库（按考核关分类：行为面 / 案例面 / 专业面）。
- 输出物模板（PRD、方案、拆解报告、答案卡）。

**规则**：每个学习单元必须产出「面试素材卡」，形成个人答案库；AI 按 rubric 评分并给出修改建议。

### M5 跟踪反馈闭环

**目的**：执行情况的透明化与自适应调整。

**指标**：每日完成率、知识掌握率（间隔重复）、输出物数量与质量分、能力雷达变化、模拟面试评分趋势。

**机制**：每日打卡、周复盘、双周复测、自适应规则（达标降级 / 落后加练 / 低完成减负）、提醒与连击激励。

### M6 面试就绪度

**目的**：回答「是否达到大厂录用标准」这个最终问题。

**组成**：

1. 模拟面试三场：行为面（项目深挖 STAR）+ 案例面（现场方案）+ 专业面（AI 知识与权衡），带追问与压力测试。
2. 评分 rubric + 判定：达到 / 接近 / 未达到目标职级录用标准。
3. 最终报告：达标判定、剩余 gap 清单、作品集 checklist（简历优化点、可复述案例、方案样本）。

## 4. 数据流

```
JD 导入 → M0 解析/映射/更新
         → M1 能力模型（域×项×行为指标×证据×权重×等级）
         → M2 测评 → 能力画像 + 优先补强清单
         → M3 8 周计划（每日任务自动组装）
         → M4 学习执行（输入/练习/拆解/输出物）
         → M5 跟踪（打卡/掌握度/评分/复测）→ 自适应调整 → 回到 M3
         → M6 模拟面试 + 达标判定 → gap 清单 → 回到 M1/M3 直至达标
```

## 5. 初始能力模型种子（基于 DeepSeek 两个 JD）

初始数据源：DeepSeek「AI 产品方向」与「Agent Harness 产品方向」两个 JD（2026-08-08 导入）。

### 知识域与关键能力项

**域 A：AI 技术理解**

- LLM 能力边界与 API（模型能力、局限、成本）
- Agent 机制：Agent Loop、Tool Use、Reasoning、Planning、Skills、MCP、Memory、Subagent、Multi-Agent
- 性能与工程概念：KV Cache、上下文工程（Context Engineering）、Harness Engineering
- Prompt Engineering 与第一手实践

**域 B：产品设计与体验**

- 场景识别与需求拆解（从用户体感、数据、定性观察出发）
- AI / 对话 / Agent 产品交互设计（降低使用门槛、提升深度、留存、粘性、转化）
- 边界条件、异常分支与失败场景的敏锐嗅觉
- 产品品味与细节感知

**域 C：数据与科学方法**

- 指标体系设计（如「Agent 是否真正深入帮助用户」的衡量指标）
- 系统化数据收集：问卷、访谈、A/B、灰度测试
- 统计分析工具与严谨的数据结论
- 用户体感、产品直觉与行为数据的结合判断

**域 D：战略与规划**

- 产品路线图规划与优先级（连接模型、算法、研发、运营、社区）
- 平台 / 开放 / 开发者产品意识
- 技术能力与用户价值之间的权衡

**域 E：工程协作与工具**

- vibe coding / AI coding（用代码与 AI 工具提升效率）
- AI 辅助原型图 / UI 设计素养
- 与研究员、工程师深度协作（模型与产品共同进化）
- 开源社区与开发者社群运营（中英文书面沟通）

**域 F：软技能**

- 项目管理：从需求到上线的快速高质量交付
- 自驱、认真细致、沟通力强、独立推进复杂项目
- 英语书面沟通（面向开源社区 / 用户社群）

**初始权重与目标等级**：按 JD 出现频率与职责优先级初步分配；核心能力（域 A/B/C）默认目标等级 L4，其余 L3。具体数值在实现阶段校准，入营测评后按用户背景微调。

## 6. 数据模型（概念级）

- JD：{ id, company, title, location, raw_text, parsed_at, requirement_items[] }
- CapabilityItem：{ id, domain, name, description, behavioral_indicators[], evidence_requirements[], weight, target_level, sources[] }
- AssessmentResult：{ date, objective_scores{}, case_scores{}, radar{}, priority_gaps[], notes }
- LearningPlan：{ week, day, tasks[{ type, content_ref, output_required, status, score }], adaptive_adjustments[] }
- ArtifactCard：{ type: 答案卡/STAR案例/拆解报告/PRD/方案, capability_refs[], content, rubric_score, feedback }
- InterviewReadiness：{ date, scores{行为面,案例面,专业面}, verdict, gaps[], portfolio_checklist[] }

## 7. MVP 范围与迭代顺序

产品开发与 8 周学习周期并行，开发由 Codex 在项目工作区内完成，不占用用户学习时间。

- 迭代 0：项目骨架（README、规格、数据目录、git）
- 迭代 1：M0 + M1——导入 2 个 DeepSeek JD，生成能力模型种子
- 迭代 2：M2——入营问卷 + 客观题 + 案例题
- 迭代 3：M3 + M4——8 周计划生成 + 首批学习内容（含 GitHub 拆解模板）
- 迭代 4：M5——跟踪看板、打卡、自适应规则
- 迭代 5：M6——模拟面试 + 就绪度判定

**非目标**（本期不做）：复杂 Web UI、多人账号、社区功能、支付、移动端。

## 8. 错误处理与风险

- **JD 解析不准**：解析后展示 diff 与冲突清单，用户确认再应用；可回滚。
- **测评信效度不足**：rubric 明确化 + AI 初评人工复核 + 双周复测校准。
- **学习时间不足**：最低必做任务 + 自动减负规则；高权重能力项优先。
- **内容供给不足**：优先覆盖目标 JD 高权重能力项；AI 实时生成知识点卡与练习题，GitHub 拆解作为深度内容主力。
- **模型/市场变化**：JD 导入功能使能力模型可持续更新。
- **产品化过早**：个人案例阶段明确不做 UI 与多用户，保持数据与工具分离。

## 9. 待确认假设

1. **交付形态**：本地 Codex Agent 教练 + Markdown/JSON 数据文件，通过任务对话跟踪；暂不做 Web 应用（如需可后续迭代）。
2. **目标岗位**：以 DeepSeek 两个 JD 为初始种子，入营问卷中可调整目标公司/职级。
3. **学习周期**：2026-08-10 起 8 周，每日 2-3 小时（最低 60 分钟）。
4. **评分标准**：模拟面试与案例题采用 1-5 分 rubric；具体分值线在迭代 5 前确定。
