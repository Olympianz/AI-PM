# LLM 能力边界与 API

LLM 是基于概率生成文本的模型：它擅长理解意图、生成内容、总结归纳，但也会产生幻觉，知识有时效局限，且无法自主访问外部数据。产品设计的第一课是明确「模型不能做什么」。

能力边界决定产品形态：需要实时信息就要接检索或工具；需要可追溯结论就要强制引用来源；需要稳定输出就要用结构化输出与校验。API 层还涉及成本与延迟，Token 用量直接决定单次交互的毛利与体验。

给 PM 的检查清单：1）哪些环节出错代价高，必须人工兜底；2）知识时效要求多高，是否需要检索增强；3）成本模型是否随使用量线性增长，有没有缓存与降级方案。

面试里最常见的追问是：如果模型回答错了，产品怎么让用户发现并补救。答案的核心不是消灭错误，而是让错误可见、可纠正、低成本。
